# 现有素材短视频精剪

将原片里真正有趣的动作或有用的表达组织成作品。用户要“完整版”时保留完整有效信息；要精彩短片时才压缩成亮点。时长由素材和用途决定，30–60 秒只是常见起点，不是硬限制。不承诺播放量。

## 先确定这条片子是什么

检查用户原片和已有项目笔记，复用已经选择的工具、缓存和可用素材。保存来源、分辨率、旋转、时长、帧率和音轨信息。制作项目副本或引用原片，避免修改原件。工作目录使用当前用户选定位置，不能照抄别人的盘符或路径。

先看片，再做编辑决定：
- 为长片生成带时间标记的缩略图索引；围绕候选动作加密取帧，并播放实际片段看衔接。
- 有重要对话时转写并核对原音。低置信度、极短且不合理的 ASR 字词不可直接做成字幕；无可靠语音的萌宠片可用明确的编辑旁白。
- 区分亲眼看过的画面、已听过的声音和仅做技术检测的内容。工具无法听音时，说明听感尚待用户预览。

写一小段分析：素材中的人物/动物、动作、重复部分、亮点时码、可成立的叙事。不要先套模板再把画面硬塞进去。

## 把分析落实为剪辑

有原素材时先读 [72 项技法地图](references/editing-techniques.md)，再读匹配的 [内容类型方案](references/footage-playbooks.md)。按当前问题选文档，不必把整个技法库塞进每次任务。

| 当前需要 | 读取 |
| --- | --- |
| 去重、自然接缝、动作/视线连续、多机位 | [连续性与剪接](references/cuts-and-continuity.md) |
| 开场、因果、悬念、蒙太奇、完整信息 | [叙事与结构](references/story-and-structure.md) |
| 呼吸、卡点、留白、快慢动作、速度坡度 | [节奏与时间](references/rhythm-and-time.md) |
| J/L cut、环境声、音乐让位、对白清理 | [声音剪辑](references/sound-editing.md) |
| 叠化、甩镜、遮挡、匹配、分屏、遮罩 | [转场与合成](references/transitions-and-compositing.md) |
| 竖屏构图、稳定、校色、字幕、封面 | [画面整理](references/picture-and-delivery.md) |

按动作或信息推进，而不是固定每几秒换镜头。通常先选 2–4 项核心技法及必要的声音字幕整理；这不是数量要求。每项都要解释如何帮助这份素材。不适用就不用，不为展示技法而增加复杂度。

制作前填写 [剪辑决策记录](examples/edit-decisions.md)：用户目标、必须保留信息、源入出点、输出时码、技法编号、采用理由、素材余量、执行方式，以及不用某技法的原因。完整版口播尤其要保留否定、条件、数字、气口和完整有效论述。趣味旁白与真实口播字幕分开，不改写现实因果。

制作时必须读 [执行边界与时码实例](references/execution-recipes.md)。基础脚本只执行已经决定的硬切、逐片段字幕、等比留边及固定混音；不会因写入一个新字段就获得转场、变速、J/L cut 或跟踪功能。进阶操作用实际可用的本地处理/时间线实现，并先渲染最难接缝的小样。缺工具或缺源素材就采用明确替代，不把计划当成完成。

基础片段记录为 EDL，读取 [EDL 与本地工具](references/local-tools.md) 后导出。进阶声画分离必须分别记录源时码与输出时码；重叠转场、变速和定格后重算全长与字幕。所有做法都以实际看片结果为依据。

术语与研究出处见 [研究来源](references/research-sources.md)。这是可扩充的常用技法库，不是“所有剪辑方法”的穷尽列表。

## 音乐与原声

优先使用用户提供且可用的音乐、明确许可的素材或本地创作的器乐。不要把随手下载的热门歌曲当成可自由发布的音乐。配套 `scripts/make_music.py` 是可选的轻快合成器器乐草稿；情绪不合适时换曲或修改旋律，不要所有视频都套同一首。

保留关键现场声，口播配乐应主动压低。混音后检查综合响度、真峰值、接缝和结尾淡出；-18 LUFS / 真峰值不高于 -1.5 dBFS 可作短片初始目标，按素材听感调整。预算与模型选择由具体请求决定；纯本地剪辑无需填 API Key。

## Hypit 可编辑预览（有需要时）

本仓库另附官方 `hypit` Skill。进行 Hypit Author/Run/Runtime 工作时先读取它，并按其引用文档执行；安装 Skill 不等于安装 CLI。

把项目素材放在项目中，以 Normalize 建立素材 Outputs，使用媒体轨、原声轨和配乐轨组成 Film。先检查 Run，再准备本地素材；后续 Run 用精确 Build ID 与 output 名的 build-record/satisfy 复用结果。只配置当前项目确实需要的本地能力，不复制他人的凭据或 Runtime 私有数据。

启动 Studio 后使用实际打印的 URL，保留 Run 位置。若交付 MP4 由 FFmpeg 导出，明确如此，不把 Studio 加载成功说成原生 Hypit 最终渲染成功。FFmpeg 模式没有 Hypit 时间线，不伪造工程验证。

## 检查与交付

检查文件解码、时长、帧率、音轨，抽查字幕和画面；在可用播放器中从头播放到结尾，区分播放测试和人工视听确认。审美问题要回到具体片段修正。

提供预览、MP4、封面及可复制的发布文案。适合时附无新增配乐版供用户换平台音乐。用户明确要求先预览再最终导出时，先交预览版并等待其反馈；其他情况下可以先交完整可修改初版。上传素材、发布账号内容、调用付费生成是独立操作，不从“剪好视频”推断其授权。

交付时列出实际采用的主要技法及对应时码，区分计划、已渲染、画面检查和试听。用项目笔记记录 EDL、剪辑决策、处理命令/工程、输出路径、采用的配乐、已完成检查、未验证事项，便于下一次按秒修改。
