# 现有素材短视频精剪

将原片里真正有趣的动作或有用的表达组织成作品。用户要“完整版”时保留完整有效信息；要精彩短片时才压缩成亮点。时长由素材和用途决定，30–60 秒只是常见起点，不是硬限制。不承诺播放量。

## 先确定这条片子是什么

检查用户原片和已有项目笔记，复用已经选择的工具、缓存和可用素材。保存来源、分辨率、旋转、时长、帧率和音轨信息。制作项目副本或引用原片，避免修改原件。工作目录使用当前用户选定位置，不能照抄别人的盘符或路径。

先看片，再做编辑决定：
- 为长片生成带时间标记的缩略图索引；围绕候选动作加密取帧，并播放实际片段看衔接。
- 有重要对话时转写并核对原音。低置信度、极短且不合理的 ASR 字词不可直接做成字幕；无可靠语音的萌宠片可用明确的编辑旁白。
- 区分亲眼看过的画面、已听过的声音和仅做技术检测的内容。工具无法听音时，说明听感尚待用户预览。

写一小段分析：素材中的人物/动物、动作、重复部分、亮点时码、可成立的叙事。不要先套模板再把画面硬塞进去。

## 把分析落实为剪辑

以动作或信息推进，而不是每几秒随意切换。可用强动作开场，再交代过程，用反应或结果结尾；是否回放亮点由节奏决定。

- 删除无效等待和重复；口播删重读、卡壳时保持句义、呼吸及前后语气。
- 不用无依据字幕把行为说成事实；趣味旁白与真实口播字幕分开。
- 竖屏保留主体，横屏素材先判断裁切会不会丢失主体；默认等比适配，不拉伸。
- 字幕使用可用的中文字体，避开主体脸部、底部平台文案和右侧按钮；检查实际手机尺寸，不能仅看 ASS 字号。
- 动作自然衔接优先。必要时使用短音频淡入淡出，避免突兀声响；有意图才加画面转场。

将每个片段的源文件、入点、出点、字幕及用途记录为 EDL。读取 [EDL 与本地工具](references/local-tools.md) 后可用配套脚本导出可修改初版。脚本不替代看片和审美判断。

## 音乐与原声

优先使用用户提供且可用的音乐、明确许可的素材或本地创作的器乐。不要把随手下载的热门歌曲当成可自由发布的音乐。配套 `scripts/make_music.py` 是可选的轻快合成器器乐草稿；情绪不合适时换曲或修改旋律，不要所有视频都套同一首。

保留关键现场声，口播配乐应主动压低。混音后检查综合响度、真峰值、接缝和结尾淡出；-18 LUFS / 真峰值不高于 -1.5 dBFS 可作短片初始目标，按素材听感调整。预算与模型选择由具体请求决定；纯本地剪辑无需填 API Key。

## Hypit 可编辑预览（有需要时）

本仓库另附官方 `hypit` Skill。进行 Hypit Author/Run/Runtime 工作时先读取它，并按其引用文档执行；安装 Skill 不等于安装 CLI。

把项目素材放在项目中，以 Normalize 建立素材 Outputs，使用媒体轨、原声轨和配乐轨组成 Film。先检查 Run，再准备本地素材；后续 Run 用精确 Build ID 与 output 名的 build-record/satisfy 复用结果。只配置当前项目确实需要的本地能力，不复制他人的凭据或 Runtime 私有数据。

启动 Studio 后使用实际打印的 URL，保留 Run 位置。若交付 MP4 由 FFmpeg 导出，明确如此，不把 Studio 加载成功说成原生 Hypit 最终渲染成功。FFmpeg 模式没有 Hypit 时间线，不伪造工程验证。

## 检查与交付

检查文件解码、时长、帧率、音轨，抽查字幕和画面；在可用播放器中从头播放到结尾，区分播放测试和人工视听确认。审美问题要回到具体片段修正。

提供预览、MP4、封面及可复制的发布文案。适合时附无新增配乐版供用户换平台音乐。用户明确要求先预览再最终导出时，先交预览版并等待其反馈；其他情况下可以先交完整可修改初版。上传素材、发布账号内容、调用付费生成是独立操作，不从“剪好视频”推断其授权。

用项目笔记记录 EDL、输出路径、采用的配乐、已完成检查、未验证事项，便于下一次按秒修改。
